# 2026-10-30 MuJoCo 初次运行与试错记录

## 1. 代码解剖理解
- **model 与 data**：model 是静态剧本（质量、形状），data 是动态现场（每一帧的位置 `qpos`、速度）。
- **仿真循环**：`while viewer.is_running()` 是主循环，`mujoco.mj_step()` 负责计算下一步的物理状态，`viewer.sync()` 负责把数据刷新到屏幕上。

## 2. 试错实录

**实验 A：修改几何与物理属性**
- **操作**：将 `rgba="1 0 0 1"` 改为 `0 1 0 1`，将质量参数修改为 `mass="20"`。
- **现象**：球体渲染颜色变为绿色。下落过程的视觉速度无明显变化。
- **我的思考**：根据牛顿经典力学，在仿真环境中重力加速度 \(g\) 恒定，故下落时间一致。但根据动量定理，质量增大意味着对地面的冲击力增大。不过仅凭视觉无法严谨判断碰撞形变（刚体引擎默认无形变），后续需打印接触力（efc_force）数值进行验证。

**实验 B：删掉 time.sleep(0.01)**
- **操作**：移除主循环中的 `time.sleep(0.01)` 代码并运行。
- **现象**：程序启动后，球体瞬间落地并静止，无法观察下落过程。
- **我的思考**：`time.sleep` 的作用是限制主循环的执行频率。若缺失该休眠指令，CPU 会以极高频率调用 `mj_step`，导致仿真时间极速流逝，无法与真实世界时间（墙钟时间）对齐。在真实的机器人控制中，必须严格控制控制循环的频率以保证实时性。

## 4. 今日实操记录：电机配置与悬停

**实验 C：添加执行器与报错解决**
- **操作**：在 XML 中 `<worldbody>` 外添加 `<actuator>` 标签，写入 `<motor joint="ball_joint" gear="0 0 1 0 0 0" />`。
- **报错**：运行时终端报错 `ValueError: Error: unknown transmission target 'ball_joint' for actuator id = 0`。
- **思考与解决**：去检查 XML，发现第 13 行的 `<joint>` 只写了 `type="free"`，没有定义 `name`。加上 `name="ball_joint"` 后，报错消失。

**实验 D：计算重力实现悬停**
- **操作**：将球的质量设为 20kg。计算重力 \(G = mg = 20 \times 9.81 = 196.2\) N。在 `while` 循环中，给 `data.ctrl[0]` 赋值 196.2。
- **现象**：运行程序，绿球稳稳停在了初始高度（Z=2），没有继续下落，也没有飞走。

**实验 E：尝试多变量控制**
- **操作**：想尝试 X 和 Y 方向的控制，在 `<actuator>` 中增加了 3 个 `<motor>`，分别对应 `gear="1 0 0 0 0 0"`、`gear="0 1 0 0 0 0"` 和 `gear="0 0 1 0 0 0"`。
- **现象与思考**：要控制三个方向，就得手写 `data.ctrl[0]`、`data.ctrl[1]`、`data.ctrl[2]`。如果以后控制几十个关节的机器人，这样手写代码非常繁琐，需要引入矩阵运算。

### 实验 H：Reset 机制与开/闭环控制

**1. 操作与现象**
* **开环（循环外赋值）**：小球悬浮。点击 Reset 后，小球坠落。
* **闭环（循环内赋值）**：小球悬浮。点击 Reset 后，小球微降瞬间被拉回，保持悬浮。

**2. 底层原理**
MuJoCo 的 Reset 动作会将所有控制指令（`data.ctrl`）清零。写在循环外只发一次指令，清零后即失效；写在 `while` 循环内部，每一帧都会重新赋予控制力。

**3. 核心顿悟**
* **控制指令必须持续下发**：真实物理系统随时面临扰动，绝不能只发一次指令就撒手不管。
* **控制频率的概念**：`time.sleep(0.01)` 和 `mj_step` 构成了控制周期，周期性刷新是保证系统稳定的前提。
* **下一步计划**：当前施加的是恒力（无论在哪都给 196.2N）。必须引入 **PID 控制**，根据当前高度（`data.qpos`）实时计算所需力，实现动态闭环。
